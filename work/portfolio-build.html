01 / THE GOAL

A portfolio I can maintain.

I wanted hiring teams to find my work quickly, understand my design background, and see the front-end technologies I'm learning. The old Webflow version was harder for me to maintain, so we moved to plain website files and GitHub Pages.

This was an AI-assisted build. I directed the design, selected content, reviewed iterations, and configured the deployment. I am continuing to study the underlying code rather than present it as something I wrote independently.

02 / PROCESS

How it works.

01

Content structure

The homepage and individual case studies use semantic HTML, real links, headings, and landmark regions.

02

Responsive layout

A shared CSS stylesheet adapts project cards, navigation, and the case studies for different screen sizes.

03

Interactive mobile menu

Vanilla JavaScript controls the menu's expanded state and lets people dismiss it.

04

GitHub Pages deployment

The website lives in a GitHub repository and is served as static files from a separate publishing branch.

03 / WORKING FEATURES

What the website can do.

Visitors can move between the home page and case studies, use responsive navigation on smaller screens, open my GitHub and LinkedIn profiles, and contact me using their email app. The site also has a skip link for keyboard navigation.

The full website is a static front-end project. It does not have a custom back end, live database, login system, or server-side API.

AI-assisted development is explicitly credited here. The design case studies elsewhere on this portfolio are concepts, not deployed full-stack apps.
04 / WHAT'S NEXT

Keep learning, keep improving.

I plan to strengthen my JavaScript skills, practice maintaining the code myself, test keyboard and mobile interactions, and later add a genuinely working application with an API and back-end component.
